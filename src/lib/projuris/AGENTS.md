# ProJuris ADV integration rules
- Calendar migration keeps paginated source snapshots and append-only owner workspace receipts; verify exact source, times and responsible user, and keep Google active until separate team approval. Why: preserve originals and block uncertain replays.

- Server only: `cliente.server.ts` and `consultas.server.ts` call the API; Ana and the browser never do. Credentials are only `PROJURIS_CLIENT_ID` and `PROJURIS_CLIENT_SECRET` (client_credentials) from the vault or a git-ignored local `.env`; never copy a key seen in chat into code, tests, logs or reports. Why: the key opens every client's data.
- The client accepts only ids from the closed list in `operacoes.ts`, never a free path. Do not add functions to delete, read files/documents, finance, hours, comments, requests, create/change tasks, hearings or attendances, users, profiles, settings, webhooks or notifications, even if the API allows them. Person/contact edits are authorized only through the reviewed Clients flow; creation of people, processes or involved parties remains a separate stage. Exception authorized by the Dra. on 2026-11-04 (agenda migration): compromisso read/create/alter operations (`tarefa.compromisso*`); delete stays forbidden (Excluir is off in ProJuris). Why: least privilege also in code, besides the ProJuris integration user's profile.
- Agenda reservations (`agenda.server.ts`) serialize through the `projuris_claim` lease (code 0), re-read the agenda under the lock, dedupe by `codigoExterno` (prefix `manageradv:`), confirm creation by read-back, and never retry a write automatically — after timeout/5xx they re-query by `codigoExterno` before deciding. Why: no overbooking, no duplicates, no false confirmations.
- 403 is `sem_permissao`: record and tell the Dra., never work around. 429/5xx/network/timeout retry with backoff; 401 renews the token once. Queue keeps at most 480 requests per minute per server instance. Why: provider limits and safe failure.
- Protect by default: only the phone marked principal identifies; duplicates never pick a person; only active processes where the person has flagCliente; missing `privado` means private and missing `segredoJustica` means secret; the "Ativo" code comes from the tipo query, never hard-coded. Why: confidentiality.
- Field names follow the public docs; list wrappers are confirmed with `tools/projuris-teste-conexao` (`--estrutura` prints names only). Why: undocumented response shapes.
- Contencioso validation may use only the official closed advanced movement, classified movement and movement indicator read queries; classified pagination excludes already obtained IDs and never implies UI equivalence without evidence. Why: investigate completeness with the existing credentials, without writes or free paths.
- Clientes and Ana use an owner-scoped persistent operational replica; senior/admin manual sync uses the existing official closed reads and exhaustive movement pagination. Current snapshots replace only after complete reads and version history is append-only. Full person writes always re-read original DTOs. Why: availability without stale overwrites or fabricated synchronization.
- Authenticated senior/admin client edits may use only closed person/contact PUT operations, with a fresh revision check, full original field preservation and read-back verification; no automatic retry after write network/5xx failure. Provider has no documented conditional-write guarantee, so cross-system concurrent edits can still conflict. Why: explicitly authorized registration updates must not imply safe PATCH semantics or silently replay writes.
- Client link (`vinculo.ts`): a unique principal-phone match is stored as a confirmed link on the conversation; otherwise Ana asks for CPF, a read-only CPF lookup creates a pending link (CPF masked, never logged) and no process data leaves until a senior/admin confirms it. Why: never pick a person by guess.
- Display names come only from `nomeClienteProjuris`: `RT|AC - <5-digit process identificador> - <NAME IN CAPS>`, joined with " / " for several active processes; never codigoPessoa/codigoProcesso; missing number or RT/AC type is flagged (`nomePendencia`), never filled with another id. Why: the Dra.'s official naming must point to the process number, not technical ids.
